# vless-aio-hardened

`vless-all-in-one`（Chil30，v3.4.10）的**加固修补版**服务端脚本：修复真实故障、为出站增加
BitTorrent / 私网拦截，并解决「升级后配置不生效」这一长期痛点。

- 上游项目：https://gitlab.com/chil30-group/vless-all-in-one
- 本仓只包含**服务端脚本** `vless-server.sh`（单文件，无依赖安装器）
- 版本基线：`3.4.10-h5`（`<上游版本>-h<本仓修订号>`）
- **升级源为本仓 GitHub，已脱离上游更新链**（版本比较 / 下载均指向本仓，不触碰上游 GitLab）

> 📖 **[使用手册 → `USAGE.md`](USAGE.md)**：安装 / 升级 / 迁移、主菜单速查、用户与配额管理、
> AnyTLS 真实证书、db.json 真相源架构、排障与常见操作速查。
>
> 🗒 **[改动清单与验证记录 → `FIXES.md`](FIXES.md)**：历次 `-h1`~`-h5` 修复的痛点、根因、
> 修复与验证取证。

## 安装（一条命令，既是安装也是升级）

```bash
wget -O vless-server.sh https://raw.githubusercontent.com/offzen/vless-aio-hardened/master/vless-server.sh
chmod +x vless-server.sh
./vless-server.sh
```

- **全新机器**：进入交互式菜单 → 选「安装协议」，按向导走完即可。
- **已装本加固版**：直接重跑上面同一条命令即升级 —— **默认就是升级**。升级自动重建配置并
  重启服务，**不重装协议、用户数据零丢失**（升级前后 `db.json` 一致）。
- 想跳过本次升级进入菜单：在「是否立即升级」提示处输 `n`；菜单里也可随时走「检查脚本更新」。

> 升级源已**脱离上游**：版本比较与下载均指向本仓 GitHub，不会从上游 GitLab 拉取任何内容，
> 升级只会拿到本加固版。

## 本版加固了什么（摘要）

| 主题 | 说明 |
|---|---|
| 数据安全 | 修复「用户列表被清空」—— `db.json` 写入改原子化 + 目录锁 + 清空护栏 |
| 出站安全 | 恒定注入 BitTorrent / 私网（RFC1918 等）拦截，Xray + sing-box 均生效 |
| 升级即生效 | `do_update` 自动重建配置并重启服务，升级完配置就落地，不用手工重建 |
| 脱离上游 | 版本源 / 下载源全指向本仓，升级只会拿到加固版；默认即升级 |
| AnyTLS | 移入 sing-box，支持多用户 / 多端口 / 真实 ACME 证书（-h2~-h4） |
| 防死循环 | 滚动 tag 不再当版本号，`/releases/latest` 语义化版本快路径（-h5） |

完整痛点 / 根因 / 修复 / 验证见 **[`FIXES.md`](FIXES.md)**；日常操作见 **[`USAGE.md`](USAGE.md)**。

## 兼容性实测

| 平台 | 结果 |
|---|---|
| Debian 13 + systemd（Xray 26.3.27） | ✅ 升级成功，用户零丢失，`Configuration OK.`，配置自动重建 + 服务自动重启 |
| Alpine + OpenRC（Xray 26.3.27） | ✅ 原子写 / 目录锁 / 定时任务均可用；多用户零丢失 |

双端口数组格式 `db.json`（一端口多用户 + 另一端口 uuid 凭证）实测通过。
